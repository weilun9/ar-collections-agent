Customer replies are classified by plain keyword rules, with no LLM. A match in the instalment / discount / extension or dispute / legal categories forces the invoice to high risk and stops all automation. L4 runtime policy layer · hard rules

These rules are Python code: they read no prompt and call no model. Constraints in a system prompt are soft (they can be ignored, bypassed by injection or forgotten in a long context); this layer is hard: it acts on a match and the agent cannot talk it round. Each rule can only make the result stricter, never looser, so adding a rule can never accidentally open a door.

L2 pre-approved templates · what the agent is allowed to say

The render function's signature is render(template_id, variables): there is no body parameter. The agent can pick a template and fill in amounts and dates, but cannot produce a sentence like "we agree you may pay in instalments". It is not that it is asked not to; it cannot.

Pre-send content gate · second layer of defence in depth

Assume layer one is bypassed (a template edited by mistake, or a variable injecting risky wording): the rendered text is scanned for forbidden words.
