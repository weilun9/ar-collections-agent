# 应收账款催收 Agent(AR Collections Agent)
### 产品方案文档 · 面试演示版

---

## 一、问题定义(Problem Statement)

### 1.1 现状痛点

某B2B贸易企业(虚拟场景:年营收约8000万,300+企业客户,账期30-60天),财务团队2人负责应收账款跟踪,销售团队20人各自维护自己客户的回款。

| 痛点 | 具体表现 | 影响 |
|---|---|---|
| 跟进不及时 | 财务每周手动导出Excel,人工判断哪些该催 | 平均逾期后**5-7天**才发出第一次提醒 |
| 漏单 | 300+客户人工盯,经常漏催中小额账款 | 每月约**8-12%**的逾期账款完全没人跟进 |
| 催收方式一刀切 | 不管客户关系深浅、金额大小,催收话术/渠道都一样 | 部分VIP客户被生硬催收,影响关系 |
| 管理层看不到全局 | 没有统一的逾期健康度视图,CFO每月靠财务口头汇报 | 现金流风险发现滞后,决策依据不足 |

### 1.2 为什么现在做(Why Now)

- 企业普遍已经在用WhatsApp Business做客户日常沟通,催收本可以复用同一渠道,而不是让客户多学一个系统
- LLM能理解"这笔账逾期了多久、这个客户历史付款习惯如何",做出比"逾期N天就发固定模板"更细腻的分级判断
- 财务/销售团队的时间应该花在"需要谈判的大额/高风险账款"上,而不是发提醒邮件

### 1.3 不做什么(Non-Goals)

明确边界,面试时经常被问到,提前想清楚:
- ❌ 不做自动扣款、自动打折、自动分期承诺——任何涉及**改变还款条件**的动作必须人工决策
- ❌ 不替代法务/催收公司的强制手段(诉讼、第三方催收)
- ❌ 第一期不做多语言/多币种(先validate单一市场再扩展)

## 二、目标用户与用户故事

### 2.1 用户画像

| 角色 | 核心诉求 |
|---|---|
| 财务专员(主要操作者) | 想从"每天盯Excel"变成"只处理系统标红的case" |
| 客户经理/销售 | 想在客户被自动催收前收到通知,必要时自己先联系,维护关系 |
| CFO/财务负责人 | 想要一份不用追着财务要的、随时能看的逾期健康度报告 |
| 企业客户(被催收方) | 想收到清晰、专业、不生硬的提醒,而不是被骚扰感 |

### 2.2 用户故事(User Stories)

```
作为财务专员,
我希望系统自动扫描每天的应收账款并按风险分级,
这样我就不用每天手动导出Excel逐条判断。

作为财务专员,
我希望轻度逾期的账款由Agent自动通过WhatsApp/邮件跟进,
这样我可以把时间集中在需要人工判断的大额/高风险case上。

作为客户经理,
我希望我名下客户进入"中风险"等级时,我能在Agent对外发送前先收到Slack通知,
这样我可以选择自己先联系,维护客户关系,而不是被动接受系统已发生的动作。

作为CFO,
我希望每周自动收到一份应收账款健康度报告,
这样我不需要每次都找财务要数据,也能及时发现现金流风险苗头。

作为企业客户,
我希望催收提醒语气专业、信息清晰(金额、到期日、付款链接),
这样我不会因为一次自动化提醒而对合作关系产生负面感受。
```

## 三、系统架构与集成设计

### 3.1 整体流程

```
[数据源] Google Sheets(模拟财务系统的应收账款表)
        ↓ 每日定时扫描
[分级引擎] 根据逾期天数+金额+客户历史 → 风险分级(轻度/中度/高风险)
        ↓
   ┌────┴────┬─────────────┐
轻度：自动跟进   中度：通知销售先介入   高风险：直接升级人工+Slack告警
   ↓                ↓                    ↓
WhatsApp/Gmail   Slack通知客户经理      Slack + 邮件通知财务负责人
自动发送提醒      +48小时缓冲期          （不自动对外发送任何消息）
        ↓
[记录层] 所有动作写回 Sheets（状态、渠道、时间、内容）
        ↓
[报告层] 每周一自动生成周报，通过 Gmail 发给 CFO
```

### 3.2 系统集成清单

| 系统 | 用途 | 数据流向 |
|---|---|---|
| **Google Sheets**(代替CRM/财务系统) | 存储应收账款主数据、客户历史付款记录、Agent处理日志 | 读+写 |
| **WhatsApp Business API** | 对客户发送催收提醒(轻度分级) | 只写(发送),回复由人工处理 |
| **Gmail API** | 对客户发送正式催收函(中/高风险的书面记录);对CFO发周报 | 只写 |
| **Slack** | 内部告警:通知客户经理"你的客户进入中风险"、通知财务负责人"高风险case需要你处理" | 只写(通知),不做自动化决策 |

**设计原则**:对外(客户)的沟通渠道(WhatsApp/Gmail)和对内(团队)的告警渠道(Slack)严格分离——这样即使Agent误判,最坏情况也是"内部多发了一条通知",而不是"对客户发错了消息"。

## 四、分级决策矩阵(核心设计)

这是这个项目最值得在面试中展开讲的部分,直接体现产品判断力和风险意识。

| 分级 | 触发条件 | Agent自主动作 | 人工介入方式 |
|---|---|---|---|
| **🟢 轻度**(Auto) | 逾期1-14天,且金额<¥50,000,且客户历史无逾期记录 | 通过WhatsApp自动发送第1次友好提醒;7天后未回应,发第2次 | 无需介入,财务专员可在周报中抽查 |
| **🟡 中度**(Notify-then-Act) | 逾期15-30天,或金额¥50,000-¥200,000,或客户有过1次逾期历史 | 先在Slack通知对应客户经理,**留48小时缓冲期**;若客户经理未响应,Agent才通过Gmail发送正式催收函 | 客户经理48小时内可以"接管"(标记为人工处理),Agent自动停止 |
| **🔴 高风险**(Human-Only) | 逾期30天以上,或金额>¥200,000,或客户提出"需要延期/打折"等还款条件变更请求 | **不自动对外发送任何消息**,仅在Slack+邮件通知财务负责人和CFO,附上账款详情和历史沟通记录摘要 | 必须人工决定下一步(继续催收/启动法务/协商还款计划) |

### 4.1 关键设计:为什么"中度"要有48小时缓冲期?

这不是技术限制,是**产品设计选择**——直接体现Agent不是要"抢在人之前行动",而是"给人优先权,人不响应才补位"。面试时这个细节很容易成为加分点:它说明你设计的是"人机协作"而不是"机器接管"。

### 4.2 关键设计:任何"还款条件变更"关键词自动升级

Agent在解析客户回复(WhatsApp/邮件)时,如果检测到客户提出"能不能分期""能不能打折""能不能延后"这类诉求,**不管当前处于哪个分级,一律强制升级为高风险、停止自动化、转人工**。这一条对应你之前问的"复杂任务逻辑不能被绕过"——规则不依赖Agent自己判断"这个诉求是否合理",而是命中关键词类别就无条件升级,这是运行时策略层面的硬规则,不是system prompt里的软约束。

## 五、风险边界与安全治理(复用7层框架)

| 层级 | 在这个项目里的具体设计 |
|---|---|
| L1 System Prompt | 明确Agent角色:"你只负责标准化提醒,任何还款条件变更必须转人工",但**不依赖这条prompt作为唯一防线** |
| L2 工具设计 | `send_reminder(customer_id, tier)`——只能发送预设模板,不能自由生成还款承诺类文本;`escalate_to_human(reason)`独立工具,权限单一 |
| L3 Agent IAM | Agent的Service Account只有Sheets的"读全部+写状态字段"权限,没有"改金额/改账期"字段的写权限 |
| L4 运行时策略(核心) | 关键词命中"分期/打折/延期"→强制升级;单日发送量超过50条→暂停并通知财务;任何超过¥200,000的账款→无论分级都不能被Agent自动处理 |
| L5 可观测性 | 每条Agent动作(发送时间、渠道、内容、触发原因)写入独立日志表,财务/CFO可随时查询"这条催收是Agent发的还是人工发的" |
| L6 熔断机制 | 单次扫描任务最多处理200条账款,超过则分批;连续5次WhatsApp发送失败自动暂停并告警 |
| L7 合规 | 客户财务数据(账款金额、联系方式)访问权限仅限财务角色;催收内容需符合当地催收行为合规要求(如禁止某些施压性话术) |

## 六、成功指标(Success Metrics)

### 6.1 核心指标(North Star + 支撑指标)

- **North Star**:平均回款周期(DSO, Days Sales Outstanding)缩短天数
- 支撑指标:
  - 逾期后首次提醒的平均响应时间(目标:从5-7天降到<24小时)
  - 逾期账款覆盖率(目标:从88-92%提升到100%,即零漏单)
  - Agent自动处理占比 vs 人工介入占比(目标:轻度分级80%由Agent自主完成)
  - 客户投诉率(催收方式导致的关系问题,目标:不高于人工催收时期)

### 6.2 反向指标(Guardrail Metrics,防止"为了效率牺牲关系")

- 高风险/中风险case的"错误升级率"(该转人工却被Agent自动处理了的比例,目标:0)
- VIP客户(自定义标签)被Agent自动催收的次数(目标:0,VIP客户默认强制转人工)

## 八、面试可能被追问的问题(提前准备)

**Q:如果Agent误判,把一个其实没问题的客户标记成高风险怎么办?**
A:高风险分级只触发"通知人工",不触发任何对外自动动作,所以误判的代价是"财务多看一眼",而不是"客户被误伤"——这是设计时刻意做的非对称风险控制:宁可误报增加人工审查,不可漏报导致自动化误伤客户关系。

**Q:客户经理没有在48小时内响应中度case怎么办?**
A:Agent按预设模板发送**正式但克制**的催收函(不是加压话术),同时记录"客户经理未响应"这一事实到周报里,这本身也是一个管理信号——反映这个客户经理的响应及时性。

**Q:这个和纯粹的RPA(规则自动化)有什么区别?**
A:RPA是"逾期N天就发固定模板",这个Agent的价值在于**动态分级判断**(结合金额、历史、客户回复语义)+ **关键词驱动的强制人工升级**,以及底层那套独立于LLM的运行时策略层——这两点RPA做不到,纯prompt驱动的Agent又控不住风险,这个方案是两者之间的平衡点。
